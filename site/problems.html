You have an error in your yaml syntax

Error

Invalid workflow file: .github/workflows/ci.yml#L9
You have an error in your yaml syntax on line 9

Symptom

A red run with no jobs, or no run at all, right after you changed the workflow.

Cause

The file is not valid YAML: wrong indentation, a tab, an unquoted value containing : , or a key under the wrong item.

Confirm

actionlint .github/workflows/ci.yml
python3 -c "import yaml,sys; yaml.safe_load(open(sys.argv[1]))" .github/workflows/ci.yml

Fix

Go to the line named and the one above it. Align keys with their siblings, use spaces only, and quote values containing : or starting with *, &, !, @ or a backtick.

Prevent

Run actionlint in your editor or as a pre-commit hook.

Practise it: You have an error in your yaml syntax. Learn it: Level 01 · Your first workflow. Open in the app.

The workflow is not valid

Error

The workflow is not valid. .github/workflows/ci.yml (Line: 4, Col: 3): Required property is missing: runs-on

Symptom

The run fails at once with a line and column, before any job starts.

Cause

Valid YAML that GitHub's schema rejects: a missing required key (runs-on, steps), an unknown key (Unexpected value 'stepz'), a bad permission name, or uses: without @ref.

Confirm

gh run view <run-id>
actionlint .github/workflows/ci.yml

Fix

Fix the key at the line and column given. Unexpected value 'x' usually means a typo or a key indented under the wrong parent.

Prevent

actionlint knows the schema; run it in CI on workflow changes.

Practise it: Required property is missing: runs-on, You have an error in your yaml syntax. Learn it: Level 01 · Your first workflow. Open in the app.

Nothing runs after a push

Error

(no run appears in the Actions tab)

Symptom

You push or open a pull request and the workflow does not appear at all.

Cause

A filter excludes the event: branches naming master instead of main, paths not matching the changed files, tags pushed to a branches-only trigger, a schedule on a non-default branch, workflows disabled on a fork, or a commit message with [skip ci].

Confirm

gh run list --workflow ci.yml --limit 5
gh workflow view ci.yml
git log -1 --format=%B   # [skip ci]?

Fix

Match filters to the real branch names and layout, add tags: for tag pushes, keep schedules on the default branch, and enable Actions on forks.

Prevent

Use workflow_dispatch to test triggers by hand; avoid paths filters on required checks.

Error

Symptom

Jobs fail instantly in a private repository; public repositories still run.

Cause

Billing applies only to private repositories (and larger runners): their included minutes ran out with no payment method or with a spending limit of zero, or a payment failed. Standard GitHub-hosted runners are free for public repositories.

Process completed with exit code 1

Error

Error: Process completed with exit code 1.

Symptom

A run step turns red; the line above the error is the command's own output.

Cause

A command in the script exited non-zero. Run steps use bash -e, so the first failing command stops the step. Some commands use 1 for normal results: grep with no match, diff with differences.

Confirm

gh run view <run-id> --log-failed
# run the same commands locally with: bash -e script.sh

Fix

Read the output just above the error. Fix the command, or accept an expected code where you call it (grep -c x f || true). Do not use continue-on-error to hide it.

Prevent

Use shell: bash (adds pipefail) and test scripts locally.

Practise it: Process completed with exit code 1, continue-on-error hides a failing test, A variable set in one step is empty in the next. Learn it: Level 01 · Your first workflow. Open in the app.

Error

Symptom

The OIDC token is issued, AWS refuses it.

Cause

The token's sub or aud does not match the role's trust policy: no environment on the job, a different branch, a pull request, or a typo in the repository name. Or the OIDC provider is missing.

Confirm

aws iam get-role --role-name <role> --query Role.AssumeRolePolicyDocument
# the job's sub: repo:<owner>/<repo>:environment:<name> or :ref:refs/heads/<branch>

Fix

Make the job match the trust policy (often environment: production), or narrow the policy to the job's exact sub. Do not widen it with wildcards.

Prevent

One role per environment, trusting one repository and environment.
